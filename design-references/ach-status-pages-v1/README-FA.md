# راهنمای نصب ACh Status Pages

این بسته شامل ۲۲ صفحه HTML مستقل است: ۱۱ سناریو در دو زبان انگلیسی (`en`) و فارسی (`fa`). هر فایل دارای CSS داخلی است و به JavaScript، تصویر و فونت خارجی نیازی ندارد.

## ۱. بازسازی فوری صفحه‌های حذف‌شده از سایت‌های فعلی

در تنظیمات NGINX سایت‌های بررسی‌شده، دو دستور `error_page 404 /404.html;` و `error_page 502 /502.html;` وجود دارند. این فایل‌ها باید داخل **Document Root واقعی همان سایت** قرار بگیرند؛ نه صرفاً پوشه‌ای با نام دامنه. مثلاً برای سایتی با Document Root برابر `/www/acdomains/example.com`:

```bash
SITE_ROOT=/www/acdomains/example.com
# ابتدا از وجود فایل‌های قبلی و مسیر درست مطمئن شوید.
ls -l "$SITE_ROOT/404.html" "$SITE_ROOT/502.html" 2>/dev/null || true
# از داخل پوشه استخراج‌شده بسته، پس از مجوز تغییر Production:
install -o www -g www -m 0644 fa/404.html "$SITE_ROOT/404.html"
install -o www -g www -m 0644 fa/502.html "$SITE_ROOT/502.html"
```

برای سایت انگلیسی، به‌جای `fa/` از `en/` استفاده کنید. بعضی سایت‌ها Document Root از نوع `/www/acdomains/example.com/public` دارند. فقط تغییر فایل HTML به Reload نیاز ندارد؛ یک نشانی فایلِ ناموجود را درخواست کنید و اطمینان بگیرید پاسخ همچنان 404 است و طراحی جدید نمایش داده می‌شود.

## ۲. مدیریت مرکزی پیشنهادی برای چند سایت

برای نگهداری بهتر، قالب‌های زبان‌ها را در مسیر جدا از سایت‌ها قرار دهید:

```text
/www/ach-status-pages/en/
/www/ach-status-pages/fa/
```

سپس برای هر سایت در مسیر ` /www/server/panel/vhost/nginx/extension/<site>/ach-status-pages.conf ` یک Include اختصاصی از نمونه `examples/site-error-alias.conf` بسازید. در نسخه فارسی، مسیرهای داخل آن را از `/en/` به `/fa/` تغییر دهید. با این روش، `error_page`های فعلی aaPanel فایل‌های مرکزی را نمایش می‌دهند و نیازی به کپی جداگانه برای هر سایت نیست. پیش از فعال‌سازی باید تضادهای NGINX بررسی، `nginx -t` اجرا، سپس با اجازه مشخص سرویس Reload و تست HTTP انجام شود. تنظیمات موقت یا سفارشی هر سایت ممکن است متفاوت باشند.

## ۳. قالب‌های پیش‌فرض aaPanel برای سایت‌های جدید

بر اساس بررسی مستقیم کد نسخه نصب‌شده در سرور NL، پنل هنگام ایجاد سایت، فایل‌های زیر را تنها در صورتی در سایت کپی می‌کند که فایل مقصد از قبل وجود نداشته باشد:

| فایل قالب aaPanel | فایل مقصد سایت جدید | قالب این بسته |
| --- | --- | --- |
| `/www/server/panel/data/404.html` | `404.html` | `en/404.html` یا `fa/404.html` |
| `/www/server/panel/data/502.html` | `502.html` | `en/502.html` یا `fa/502.html` |
| `/www/server/panel/data/defaultDoc.html` | `index.html` | `en/new-site.html` یا `fa/new-site.html` |

برای جایگزینی قالب‌ها ابتدا Backup بگیرید. این تغییر روی سایت‌های موجود اثری ندارد و با آپدیت aaPanel ممکن است بازنویسی شود. اگر هم‌زمان وب‌سایت‌های فارسی و انگلیسی ایجاد می‌کنید، از یک زبان پیش‌فرض در aaPanel استفاده کنید و زبان سایت خاص را جدا انتخاب کنید.

## ۴. صفحات خاص

- **سایت متوقف‌شده:** فایل قدیمی `/www/server/stop/index.html` است. می‌توانید در صورت تأیید، قالب `stopped.html` را جایگزین کنید. اما جایگزینی HTML کد HTTP را به 503 تغییر نمی‌دهد؛ باید رفتار واقعی VHost بررسی شود.
- **دامنه متصل‌نشده:** `/www/server/nginx/html/index.html` یکی از صفحه‌های پیش‌فرض است، ولی لزوماً در پاسخ دامنه ناشناخته نمایش داده نمی‌شود. روی NL، خود `ach.li` فعلاً `default_server` است؛ برای پاسخ درست باید تنظیمات دامنه پیش‌فرض و TLS جداگانه بررسی شوند. نتیجه نباید 200 موفق باشد.
- **خطای عمومی:** فایل `/www/server/nginx/html/50x.html` تنها زمانی اثر می‌گذارد که تنظیمات فعال NGINX به آن ارجاع داده باشند.
- **خطاهای Cloudflare:** ممکن است در Edge تولید شوند و از قالب Origin استفاده نکنند.

## ۵. اصول و آزمون‌ها

صفحات 404 و 502 باید همان کد HTTP واقعی را حفظ کنند. WordPress ممکن است 404 را خودش بسازد؛ برای نمایش قالب NGINX نباید بدون بررسی `fastcgi_intercept_errors` را فعال کرد. قالب‌ها `noindex,nofollow` هستند، پس صفحه خطای موقت را جایگزین پاسخ 200 نکنید.

پس از نصب، وضعیت HTTP، محتوای HTML، بارگذاری فایل‌های معمولی، `/.well-known/` و مسیرهای امنیتی را کنترل کنید. تغییرات VHost باید Backup، تست `nginx -t`، Reload کنترل‌شده و برنامه Rollback داشته باشند. هیچ‌یک از این فایل‌ها مشکل امنیتی دسترسی به `.htaccess` را حل نمی‌کنند؛ آن موضوع در Issue #2 پروژه Customizer ثبت شده و مستلزم اصلاح قواعد NGINX است.

**وضعیت تحویل:** این بسته فقط روی محیط محلی ساخته و با Chromium بررسی شده است؛ هنوز روی سرورهای Production نصب نشده است. فایل‌های منبع برای ویرایش و بازسازی نسخه‌های جدید داخل پوشه `source/` هستند.
