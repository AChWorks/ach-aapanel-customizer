# Native origin-local Hosts diagnostics — actual isolated aaPanel guest QA (2026-11-04)

**Candidate:** PR #13, development-only native Customizer `0.1.8`, after integrating the already-reviewed PR #16/#18 UI and R2/R3 Monitor controls from `main` `7bb9b3148c47e2eaa70f966d4e0f692c4feb7d29`. This is source-bound engineering evidence, **not** independent review, Release or Production authorization.

**Environment:** reused isolated Debian 12 QEMU guest with authenticated aaPanel **8.0.7** and Nginx **1.28.3**. All actions used the permitted real Chromium session and aaPanel's native **App Store → Third-party Plug-ins → Import plugins → Install / Setting** controls. No credentials, session data, private guest entrance, test website names or raw `/etc/hosts` contents are reproduced here.

## Confirmed installation and runtime lifecycle

1. Merged source candidate `b7e077940bb10a2617fffd09ca6f68617d52fd7c` initially produced reproducible unreleased `0.1.8` ZIP SHA-256 `16bfd48aa325313c3caf4c131f25883be70c7c83c13f10a5452f378854e9f011`, 38 entries. Import completed with **Installation succeeded!**; the Installed row displayed Customizer 0.1.8.
2. The native `get_overview` and `get_sites` requests then failed with HTTP 500, including the explicit guest diagnostic `ImportError: cannot import name 'native_site_snapshot' from 'ach_customizer_hosts'`. The candidate ZIP was independently inspected: its Hosts module **does define** the helper, and the Python main entrypoint imported it. The observed failure was a Python module-memory/version mismatch during in-place replacement, not proof that the package omitted the function.
3. The legitimate aaPanel header **Restart → Restart panel → Confirm** (explicitly **not** `Restart server`) was used once in this **non-production guest**. The Panel HTTPS connection reset temporarily while the panel process restarted. After it became available again, the genuine read-only `get_overview` and `get_sites` requests returned **HTTP 200** and valid results (Inventory schema 2, **2** lab site records). This strongly supports a stale loaded module as the cause; it does not establish cross-version aaPanel update guarantees.
4. To avoid this single Hosts helper mismatch taking down unrelated plugin endpoints in future in-place updates, the subsequent candidate isolates the newer helper import inside the **authorized Hosts action**. A simulated cached older module missing that helper now leaves Overview functional, fails Hosts with an actionable controlled error, and retains the full-primary-admin-first authorization gate. The new regression test passes; no automatic reload or privileged fallback is added.
5. The revised development ZIP was independently rebuilt twice with **identical bytes**: **38** members, SHA-256 **`b72cbe1ec27a203d36bc2fb59beffdb5f85995e3f9f64f2a02264dc6d5d86f87`**. Its package includes the fail-isolated Python handler and native Hosts UI. The revised ZIP was **again imported normally** into the same QEMU guest and returned **Installation succeeded!**. Without another Panel restart, real `get_overview`, `get_sites` and `inspect_local_hosts` all returned **HTTP 200** and successful schema-valid responses.

## Actual native read-only acceptance

- Websites first load: two native rows, a placeholder plus **two** selectable site choices; Hosts Inspect remains disabled until choosing an inventory-backed site.
- Operator selects one available lab site and activates **Inspect local hosts**. Response schema **1**, `read_only=true`, `fix_supported=false`, state **No Local Loopback Entry**, 0 matching entries and a valid 64-hex file SHA-256. The UI shows the state and explicitly avoids any inference about remote Gateway/public DNS reachability. The operation uses the guest's **origin-local** `/etc/hosts`; it does not change the file or run a DNS query.
- Reentering Websites from Overview reuses the loaded snapshot and preserves the selected site and inspection text, with **no redundant `get_sites` read**.
- A **browser-only** synthetic HTTP 503 intercepted exactly one read-only Website Refresh. The UI revoked the previously selected Hosts target and prior inspection evidence, showed an unavailable status, kept Inspect disabled and allowed Refresh. Removing the interception and using the real Refresh recovered both lab sites and kept Inspect disabled until an explicit new selection. The synthetic 503 was **not forwarded** to aaPanel.
- Source-side concurrency tests additionally cover Hosts invalidation during pending/unverified Monitor policy, stale in-flight responses, malformed binding snapshots and identity drift. The real browser did **not** send a Monitor write.
